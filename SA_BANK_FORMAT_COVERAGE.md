# South African bank export coverage audit

Research date: 25 October 2026. The detailed table records the baseline before v5.2 additions. This is an evidence register, not a claim that all bank exports work.

## v5.2 implementation update

The release now adds conservative single-account QIF Bank and OFC adapters, plus the official FNB/RMB Stmnt3 RSA/CUR/version3 ASCII subset. `Effective Date` and `Effective Value Date` are recognized table-date aliases. The current synthetic regression suite contains 126 tests; actual Mac results are published on this repository's Actions page. QIF requires its own explicit date-order choice for ambiguous dates. Stmnt3 validates counters, credit/debit controls, account/currency consistency and segment balances. None of these changes certifies every current export channel from the named banks.

PDF/image input, the other proprietary enterprise layouts and undocumented bank-specific schemas remain gaps. This version includes an offline support-scope window so users can see those limits before conversion. Official specifications are linked rather than copied; all published fixtures are fictional.

## What is currently proved

- The public synthetic suite has 57 passing tests. It proves specific parser behaviours, not end-to-end certification for a named bank's current export channel.
- Implemented families: headed CSV/TSV/TXT (comma, semicolon, tab, pipe), XLS/XLSX (including selected HTML/text files with an XLS extension), OFX/QFX, a single-account booked-entry camt.053 subset, MT940, and three exact legacy 7/8-column layouts.
- There is no named-bank profile registry or current official-bank fixture set. The legacy layouts have synthetic tests but cannot responsibly be attributed to a specific bank from their code alone.
- Current accepted extensions: `.csv .tsv .txt .xlsx .xls .ofx .qfx .xml .mt940 .sta`. No PDF/image/OCR, QIF, OFC, SAP, Pastel, Multicash, proprietary fixed-width, MT950, BAI or ZIP-input parser is implemented in this snapshot.
- Generic XML is **not** supported: `.xml` routes to camt; HBZ/XML or any other proprietary XML cannot be counted as camt. OFX currently does not claim an independent opening/closing balance reconciliation.

Status terms below: **Generic candidate** means a supported family exists but this bank's exact layout still needs a documented schema plus synthetic regression. **Missing** means the file family is absent. **Unverified** means primary public evidence did not establish the exact export family or layout. No bank below is marked fully certified.

## Scope of “all South African banks”

The [SARB register](https://www.resbank.co.za/en/home/what-we-do/Prudentialregulation/sa-registered-banks-and-representative-offices) separates locally controlled banks, foreign-controlled banks, mutual banks and foreign branches; these lists change. The tables above include the July2026 locally-controlled names plus the foreign-controlled and mutual-bank lists found through that register. They are not an exhaustive audit of every product/channel.

The [September2026 foreign-branch list](https://www.resbank.co.za/content/dam/sarb/publications/prudential-authority/sa-registered-financial-banks-and-rep-offices/2026/Branches%20Foreign%20as%20at%20September%202026.pdf) additionally includes Bank of China, Bank of Communications, Bank of Taiwan, Citibank, China Construction Bank, Deutsche Bank, Goldman Sachs, JPMorgan Chase, Standard Chartered and State Bank of India. Their SA-specific export schemas were not audited here, so each remains unverified. Postbank and co-operative-bank/product channels would require an explicitly maintained additional inventory. Foreign representative offices should not be counted as transaction-exporting banks solely because they appear on a contact register.

## Actionable FNB/RMB specifications

The following are links to official specifications, retrieved locally for inspection; **do not redistribute the full documents in the public test repository**. All are older specifications and must be version-labelled.

1. [Basic CSV, March2014](https://www.online.fnb.co.za/rhelp_1_15/OBE_RMB_Downloads/assets/docs/Statement_Type_-_CSV.pdf): effective date is explicitly the interface date, encoded CCYYMMDD. Fields include description, reference, accrued service fee, a **service-fee** debit/credit indicator, transaction amount and calculated balance. Negative transaction amounts are debits. `Effective Date` and `Effective Value Date` are absent from the current date aliases. Adding aliases is safe only after tests establish that accrued service fees and their D/C indicator are not applied a second time to transaction amount. `Service Fee` must not silently become a transaction-sign column. The document describes separate statement metadata; a header alias alone does not implement all metadata/balance validation.
2. [CSV Date Number, March2014](https://www.online.fnb.co.za/rhelp_1_15/OBE_RMB_Downloads/assets/docs/Statement_Type_-_CSV_Date_Number.pdf): headerless rows mix account metadata, opening balance and statement context. Transaction dates use day/month without year; statement date uses a full year. This needs an explicit layout adapter with year-rollover and statement-balance tests, not a generic header guess.
3. [CM558 CSV, March2014](https://www.online.fnb.co.za/rhelp_1_15/OBE_RMB_Downloads/assets/docs/Statement_Type_-_CM558_CSV.pdf): account, interim and statement record families differ; date/year context and amount-scale notes need reconciliation. Do not implement implied cents from the filename alone; specification prose contains conflicting notes about decimals.
4. [Stmnt3](https://www.online.fnb.co.za/rhelp_1_15/OBE_RMB_Downloads/assets/docs/Statement_Type_-_Stmnt_3.pdf): fixed250-character H/T records. Published positions specify account15–30, record kind44; header opening81–93/sign94, closing95–107/sign108, currency241–243/version250; transaction effective date45–52, amount68–80/sign81, description178–219/reference220–249. Amounts use implied cents. A conservative dedicated adapter is possible with strict length/country/version/account/count/total/balance validation and synthetic records. It is absent now.
5. [QIF](https://www.online.fnb.co.za/rhelp_1_15/OBE_RMB_Downloads/assets/docs/Statement_Type_-_QIF.pdf) and [OFC](https://www.online.fnb.co.za/rhelp_1_15/OBE_RMB_Downloads/assets/docs/Statement_Type_-_OFC.pdf) are official links; another agent is researching adapters. Their existence proves demand, not implementation.

## Audit recommendations and remaining work

Use “covers the listed formats, with bank-specific status shown before conversion”; do not say “all South African bank exports supported”. Maintain a machine-readable matrix keyed by bank, product, channel, format, schema version, evidence URL and synthetic test IDs.

The first implementation priorities (QIF/OFC, conservative Stmnt3 and FNB date aliases) are included in v5.2. Remaining work includes complete FNB CSV metadata/fee semantics and the exact Standard Bank/Absa/Nedbank enterprise schemas. Generic table mapping remains useful but cannot replace bank-specific confirmation of signs, fee treatment, dates and independent balance controls.

PDF and image support is a separate substantial feature: text-based PDF extraction first, encryption handled locally with an explicitly supplied password, multi-line descriptions and account boundaries, then OCR requiring review for uncertain dates/amounts. No PDF/OCR result should be silently certified because its balance happens to match. Missing format preflight should explain the exact gap before output.
